# QEWC v3 持续学习实验报告

## 1. 先说结论

这轮实验回答了三个问题。

第一，EWC 能不能减轻连续训练造成的遗忘？在专门制造任务冲突的 Stress 实验中，能。EWC 把平均遗忘降低了 `37.0%`；把任务顺序反过来后，仍降低了 `48.5%`。在这次固定模型的配对测试中，改善大于测量噪声，但还不是“问题已经解决”。

第二，EWC 是否在所有场景都明显更好？不是。Realistic 任务之间本来就几乎不冲突，SEQ 没有多少东西可忘，因此 EWC 的优势很小。当前数据不能证明它在现实噪声序列中普遍必要。

第三，最终模型能不能直接用于真实硬件数据？不能。它在合成 OOD 数据上表现不错，但在 Willow 硬件数据上，所有神经预解码器都让最终错误率变高。这个结果直接否定了“零微调即可部署”的说法。

| 问题 | 直接答案 |
|---|---|
| Stress 中是否发生遗忘？ | 是。SEQ 学新任务后，四个旧任务都变差。 |
| EWC 是否减轻遗忘？ | 是。在本次 seed 的两个任务顺序中都有效，但没有达到预设的 50% 强效果线。 |
| EWC 是否优于等存储 Replay？ | 是。错误率和遗忘都更低，代价是计算更慢。 |
| Realistic 轨道是否证明 EWC 必要？ | 否。该轨道本身几乎没有遗忘。 |
| 合成 OOD 是否成功？ | 按最终 LER 看，是；EWC 最低。但这不是硬件数据。 |
| Willow 零微调是否成功？ | 否。所有神经方法都明显差于直接 PyMatching。 |
| 现在能否声称可部署？ | 不能。真实硬件数据失败，而且端到端速度也没有优势。 |

这仍是单个训练 seed 的实验。它能说明“这次训练发生了什么”，不能说明换一个随机初始化和数据顺序后一定如此。

## 2. 名词怎么读

所有错误率都按小数记录。例如 `0.089` 就是 `8.9%`。两个错误率相差 `0.001`，等于相差 `0.1` 个百分点。

| 名词 | 直白解释 | 好坏方向 |
|---|---|---|
| LER | 逻辑错误率。一次解码最终答错的概率。 | 越低越好。 |
| Final Avg LER / FALER | 训练全部结束后，T0 到 T4 五个任务的平均 LER。 | 越低越好。 |
| AIP | 每个训练阶段都考一次已学任务，再把全过程成绩平均。它防止只看最后一次考试。 | 越高越好。 |
| forgetting / AF | 学完一个任务后，它后来退步了多少；AF 是所有旧任务退步的平均值。0 表示没忘，负数表示后来反而进步。 | 越低越好。 |
| BWT | 学新任务对旧任务的平均影响。负数表示旧任务被损害，正数表示旧任务反而受益。 | 越高越好。 |
| FWT | 还没正式训练新任务前，旧知识是否已经帮到了它。负数表示旧知识反而造成干扰。 | 越高越好。 |
| AG | 持续学习模型刚学会一个新任务时，与只学该任务的 Oracle 相差多少。0 表示与 Oracle 相同，正数表示学习受阻，负数表示旧知识帮了忙。 | 不为正最好。 |
| SEQ | 最普通的顺序微调：T1 学完再学 T2，不采取防遗忘措施。 | 基线。 |
| EWC | 学新任务时，限制模型不要大幅改动对旧任务重要的参数。 | 本实验的主方法。 |
| A101-HTNet | 本实验使用的神经网络结构名称。A101 是其中一组固定结构开关的编号。 | 所有方法使用同一结构。 |
| Fisher | EWC 用来估计“哪些参数对旧任务重要”的权重。 | 不是性能分数。 |
| Replay | 保存少量旧样本，学新任务时穿插复习。 | 对照方法。 |
| Mix-total | 同时混合五个任务训练，总训练步数与 SEQ/EWC 相同。它能看全部任务数据。 | 联合训练参照。 |
| Mix-exposure | 同样混合训练，但保证每个任务获得与顺序训练相同的曝光量，因此总计算多 25%。 | 额外预算参照。 |
| Oracle | 只训练一个目标任务的模型，用来估计该任务在当前预算下能学到多好。 | 参照上限，不是可部署方案。 |
| T0–T4 | T0 是初始噪声任务；T1 到 T4 是随后学习的四种噪声变化。 | 任务编号。 |
| Stress / Realistic | Stress 故意选冲突大的任务；Realistic 使用更接近现实演化的任务。 | 两条实验轨道。 |
| OOD | 分布外测试，即测试数据与训练数据不完全同分布。 | 检查泛化。 |
| Willow | Google Willow 表面码实验数据。这里用它检查真实硬件域的零微调泛化。 | 硬件测试集。 |
| syndrome density | syndrome 中值为 1 的比例，可粗略理解为解码器还要处理多少异常信号。 | 对残差而言通常越低越省后端工作。 |
| residual syndrome | 神经预解码器先处理一遍后，留给 PyMatching 的 syndrome。 | 后端输入。 |
| PyMatching | 根据 syndrome 做最终匹配解码的传统算法。 | 最终后端和直接基线。 |
| shot | 一次独立的量子纠错采样和解码。 | 样本数。 |
| seed | 控制随机数据流和训练随机性的编号。 | 用于复现。 |
| checkpoint | 某个训练阶段保存下来的模型参数。 | 用于固定模型评测。 |
| d / r | d 是表面码距离，r 是纠错轮数；更大通常意味着问题规模更大。 | 实验规模。 |
| X/Z basis | 两种测量基。每个正式结果都同时评测 X 和 Z。 | 数据分组。 |
| optimizer step / batch size | step 是模型更新一次参数；batch size 是一次更新使用多少样本。 | 训练预算。 |
| lambda / gamma | lambda 控制 EWC 保护旧参数的力度；gamma 控制更早任务的重要性保留多少。 | 超参数，不是结果指标。 |
| BCE / NLL | 训练和验证使用的概率损失。它衡量预测概率是否合理，不等同于最终 LER。 | 越低越好。 |
| GPU-hour | 一张 GPU 连续运行一小时所用的计算量。两张 GPU 各跑一小时就是 2 GPU-hours。 | 越低越省计算。 |
| μs/shot、μs/round | μs 是百万分之一秒；前者是每个样本的耗时，后者是每轮纠错的耗时。 | 越低越快。 |
| 后端 / 端到端 | 后端只指神经模型之后的 PyMatching；端到端还要加上神经前向、数据搬运等全部时间。 | 部署必须看端到端。 |
| 神经网络前向 | 把输入送进模型并得到预测的计算过程。 | 是总延迟的一部分。 |
| 零微调 | 把训练好的模型直接放到新数据上，不再更新参数。 | 最严格的泛化测试。 |
| 配对比较 | 让两个方法解答完全相同的 shot，再比较谁对谁错。这样能消除测试题不同造成的噪声。 | 用于方法差值。 |
| 95% CI / Wilson CI | CI 是有限样本造成的不确定区间。方法差值的配对 CI 若跨过 0，就不能排除两者相同；Wilson CI 是单个错误率使用的区间算法。 | 区间越窄，测量越精确。 |
| run | 一套配置从训练到保存结果的完整执行。S1、R2 等是 run 编号。 | 实验记录单位。 |
| Fisher-weighted drift | 参数变化量按 Fisher 重要性加权后的诊断值，用来检查 EWC 保护了哪些参数。 | 不是 LER，不能直接排方法名次。 |

## 3. 实验设置

所有方法从同一个 T0 模型出发，再依次学习 T1 到 T4。这样比较的是“防遗忘方法”，不是不同起点或不同模型大小。

- 模型是 A101-HTNet，共 `650,332` 个参数。`branch_mixer=true` 允许不同特征分支交换信息，`axis_channel_gate=false` 表示不启用轴向通道门控，`input_skip_head=true` 让输入通过捷径连接到输出头。它们在所有正式运行中保持不变。
- 训练和主评估使用 `d=9, r=9`，同时测试 X、Z 两种测量基。
- Stage-0 checkpoint `HTnet.0.97.pt` 是所有持续学习运行的共同起点，只加载模型参数，不沿用旧优化器状态。
- 每个新任务训练 `1,000` 次参数更新，每次使用 `512` 个样本。四个新任务合计 `4,000` 次更新，即 `2.048M` 个训练样本。
- 正式测试中，每个任务、每个测量基使用 `65,536` 个固定 shot。所有 checkpoint 都考完全相同的题，因此方法间可以逐 shot 配对比较。
- EWC 使用 `lambda=43.87539484535376` 和 `gamma=1.0`；每个阶段用 `65,536` 个样本估计 Fisher 参数重要性。
- Replay 最多保存 `594` 个旧样本，约占 `5.23 MB`。这个大小与 EWC 的额外状态基本相同，避免用更多存储换成绩。
- 训练 seed 固定为 `20260907`，正式测试 seed 固定为 `20260916`。只有一个训练 seed，这是本报告最重要的限制。

## 4. 核心结果

### 4.1 Stress：高冲突顺序

任务顺序是 `T1 → T3 → T2 → T4`。这组任务故意挑得比较冲突，用来检验模型是否会“学了新的，忘了旧的”。

直接答案：SEQ 确实忘了旧任务；EWC 减轻了遗忘，同时没有牺牲最终平均错误率。

| Run | 方法 | 最终平均 LER，低好 | 全过程成绩 AIP，高好 | 平均遗忘 AF，低好 | 旧任务影响 BWT，高好 | 新任务预迁移 FWT，高好 | 平均 AG，不为正好 |
|---|---|---:|---:|---:|---:|---:|---:|
| S1 | SEQ | 0.089247 | 0.924864 | 0.003826 | -0.003801 | -0.005300 | -0.000044 |
| S2 | EWC | 0.088631 | 0.925818 | 0.002409 | -0.002237 | -0.004082 | 0.000750 |
| S3 | Replay | 0.092334 | 0.923849 | 0.005320 | -0.005270 | -0.005419 | 0.002346 |
| S4 | Mix-total | 0.088795 | 不适用 | 不适用 | 不适用 | 不适用 | 不适用 |
| S7 | Mix-exposure | 0.088268 | 不适用 | 不适用 | 不适用 | 不适用 | 不适用 |

把小数换成百分比更容易理解：SEQ 最终平均错误率是 `8.9247%`，EWC 是 `8.8631%`，EWC 低 `0.0616` 个百分点。两者最终总体成绩接近。主要差别在遗忘：SEQ 平均忘掉 `0.3826` 个百分点，EWC 忘掉 `0.2409` 个百分点，减少 `37.0%`。

SEQ 的四个旧任务都退步了。T0 退步 `0.1053` 个百分点，T1 `1.1024` 个百分点，T3 `0.1373` 个百分点，T2 `0.1854` 个百分点。四个 95% 区间都完全高于 0，因此这些退步不能用有限测试样本的随机波动解释。

EWC 并不是让每个任务都明显变好。与 SEQ 逐任务比较时，只有 T1 的改善区间明确低于 0。T0、T2、T3 的改善还不足以排除“其实没差”；最后学习的 T4 轻微变差 `0.0565` 个百分点，但区间跨 0，也低于预设的 5% 相对恶化线。

AG 检查的是 EWC 有没有因为保护旧知识而学不好新任务。S2 的最大相对 AG 出现在 T1，为约 `1.83%`。设计文档没有写明数值容忍线，所以 OOD 启动前采用了“最大相对 AG 小于 5%”的补充规则。这项检查通过，但该 5% 规则不是原设计中已经写死的数字。

结论：在高冲突任务上，EWC 有效减轻了遗忘。效果中等，不应写成“解决了灾难性遗忘”。

### 4.2 Realistic：自然顺序

任务顺序是 `T1 → T2 → T3 → T4`。这条轨道更接近逐渐变化的现实噪声，而不是故意制造冲突。

直接答案：SEQ 本来就几乎没有遗忘，因此这里看不出 EWC 是否必要。

| Run | 方法 | 最终平均 LER，低好 | 全过程成绩 AIP，高好 | 平均遗忘 AF，低好 | 旧任务影响 BWT，高好 | 新任务预迁移 FWT，高好 | 平均 AG，不为正好 |
|---|---|---:|---:|---:|---:|---:|---:|
| R1 | SEQ | 0.067024 | 0.944777 | 0.000751 | -0.000751 | -0.001907 | 0.000074 |
| R2 | EWC | 0.066644 | 0.945181 | 0.000582 | -0.000572 | -0.000832 | -0.000221 |
| R3 | Mix-total | 0.066663 | 不适用 | 不适用 | 不适用 | 不适用 | 不适用 |
| R4 | Replay | 0.068730 | 0.943874 | 0.001728 | -0.001570 | -0.002665 | 0.001389 |
| R5 | Mix-exposure | 0.066896 | 不适用 | 不适用 | 不适用 | 不适用 | 不适用 |

SEQ 的平均遗忘只有 `0.0751` 个百分点，EWC 是 `0.0582` 个百分点。最终平均错误率从 SEQ 的 `6.7024%` 变为 EWC 的 `6.6644%`，只低 `0.0380` 个百分点。逐任务看，只有 T2 的改善有明确配对证据：差值为 `-0.1511` 个百分点，95% 区间是 `[-0.2695, -0.0326]` 个百分点；其余四个任务都不能排除两者相同。

Replay 的最终平均错误率为 `6.8730%`，比 EWC 和 SEQ 都高。Mix-exposure 与 SEQ、EWC、Mix-total 的逐任务差值全部跨 0，没有证据说明多 25% 训练预算带来了稳定收益。

结论：Realistic 任务之间的干扰很弱。这里的结果不能用来证明 EWC 普遍有效，也不能证明它普遍无效；实验缺少足够的遗忘信号。

### 4.3 Stress：反向顺序

把同一批 Stress 任务改成 `T4 → T2 → T3 → T1`，是为了检查结论是否只依赖某一个顺序。

| Run | 方法 | 最终平均 LER，低好 | 全过程成绩 AIP，高好 | 平均遗忘 AF，低好 | 旧任务影响 BWT，高好 | 新任务预迁移 FWT，高好 | 平均 AG，不为正好 |
|---|---|---:|---:|---:|---:|---:|---:|
| S5 | SEQ | 0.095103 | 0.929937 | 0.011089 | -0.011089 | -0.002497 | -0.000011 |
| S6 | EWC | 0.091508 | 0.930986 | 0.005709 | -0.005709 | -0.001490 | 0.000875 |

反向顺序的遗忘更严重。SEQ 平均忘掉 `1.1089` 个百分点，EWC 为 `0.5709` 个百分点，减少 `48.5%`。最终平均错误率也从 `9.5103%` 降到 `9.1508%`，降低 `0.3595` 个百分点。

代价出现在最后学习的 T1：EWC 比 SEQ 高 `0.4082` 个百分点，95% 区间为 `[0.2700, 0.5463]` 个百分点。也就是说，EWC 保住了更多旧知识，但新任务学得稍差。相对恶化仍低于预设的 5% 上限。

结论：换一个任务顺序后，EWC 仍然减轻遗忘，所以主结果不是单一顺序造成的巧合。不过它清楚展示了稳定性与可塑性的交换：保护旧任务会妨碍一点新任务学习。

## 5. 补充实验

这些实验检查两个问题：多给联合训练一些预算是否更好，以及 Realistic 轨道中的 Replay 和 Oracle 是否改变主结论。

- S7 把 Stress Mix 的训练更新从 `4,000` 次增加到 `5,000` 次。最终平均错误率从 `8.8795%` 降到 `8.8268%`，改善 `0.0528` 个百分点。五个任务中只有 T0 的改善区间不跨 0，其余任务没有明确差别。
- R4 是 Realistic Replay。它的最终平均错误率为 `6.8730%`，平均遗忘为 `0.1728` 个百分点，两项都差于 R2 EWC。
- O5 到 O8 是四个 Realistic 单任务 Oracle。它们不是候选方法，只用于计算 AG，判断持续学习是否妨碍新任务学习。
- R5 给 Realistic Mix-exposure `5,000` 次更新。最终平均错误率为 `6.6896%`，没有明确优于只用 `4,000` 次更新的 Mix-total。

结论：增加 25% 联合训练预算没有带来稳定、逐任务可重复的改善。补充实验不改变核心结论。

## 6. 存储和计算成本

EWC 和 Replay 都会为旧知识付出额外存储。为公平比较，本实验把两者都控制在约 `5.2 MB`：EWC 保存重要参数权重和参考参数，共 `5,246,466` bytes；Replay 保存 `594` 个旧样本，共 `5,228,710` bytes。两者相差不到 1%。

| 轨道 | 方法 | 总 GPU-hours | 怎么理解 |
|---|---|---:|---|
| Stress | SEQ | 0.753 | 最便宜的顺序训练基线。 |
| Stress | EWC | 0.936 | 包含额外的 Fisher 计算。 |
| Stress | Replay | 0.771 | 包含重建样本缓冲区的时间。 |
| Stress | Mix-exposure | 0.964 | 比主方法多 25% 更新次数。 |
| Realistic | SEQ | 0.746 | 顺序训练基线。 |
| Realistic | EWC | 0.926 | 包含 Fisher 计算。 |
| Realistic | Replay | 0.760 | 包含缓冲区重建。 |
| Realistic | Mix-exposure | 0.947 | 比主方法多 25% 更新次数。 |

在 Stress 中，EWC 比 Replay 多用约 `21%` GPU 时间；Realistic 中多用约 `22%`。所以完整结论不是简单的“EWC 最好”，而是：在相同额外存储下，EWC 的错误率和遗忘更低，但 Replay 更省计算。

Fisher-weighted drift 衡量模型改动了多少“EWC 认为对旧任务重要”的参数。S2、R2、S6 的最终值分别为 `0.01115`、`0.01117`、`0.03488`。它是诊断量，不是解码成绩，也不能直接拿三个数字排方法名次。逐层结果保存在各 run 的 `diagnostics/` 和 `ewc_telemetry.json`。

## 7. Willow 真实硬件测试

Willow 测试使用 `d=5` 和 `d=7`、`r=10`、X/Z 两种测量基，共 10 个数据 case 和 `500,000` 个 shot。模型没有在 Willow 上继续训练，这就是“零微调”。

直接答案：失败。神经预解码器减少了 syndrome 中的 1，却增加了最终逻辑错误。最终解码是否正确比 syndrome 是否稀疏更重要。

| 方法 | LER | 换成百分比 | 95% Wilson CI |
|---|---:|---:|---:|
| 直接 PyMatching | 0.049974 | 4.9974% | [0.049373, 0.050581] |
| EWC + PyMatching | 0.092216 | 9.2216% | [0.091417, 0.093021] |
| Mix + PyMatching | 0.093468 | 9.3468% | [0.092664, 0.094278] |
| SEQ + PyMatching | 0.093674 | 9.3674% | [0.092869, 0.094485] |
| Replay + PyMatching | 0.095704 | 9.5704% | [0.094892, 0.096523] |

EWC 是四个神经模型中最好的。它比 SEQ 少 `0.1458` 个百分点的错误，比 Mix 少 `0.1252` 个百分点，比 Replay 少 `0.3488` 个百分点；这些配对区间都不跨 0。但这只是“神经方法内部第一”。与直接 PyMatching 相比，EWC 反而多 `4.2242` 个百分点，错误率接近翻倍。

原始 syndrome density 是 `7.208%`。神经处理后，EWC、Mix、SEQ、Replay 的残差 density 分别降到约 `0.906%`、`0.902%`、`0.916%`、`0.974%`。这说明它们确实删掉了大量 syndrome 事件，却也删错或改错了足以影响逻辑结果的事件。低 density 不能代替低 LER。

速度也没有形成端到端优势。神经网络前向约需 `42 μs/shot`。直接 PyMatching 约为 `1.41 μs/round`，10 轮粗略合计 `14.1 μs/shot`；EWC 残差 PyMatching 约为 `0.73–0.75 μs/round`，加上神经前向后约为 `49 μs/shot`，还没有计入其他开销。换句话说，这条流水线目前既更慢，也更容易答错。

结论：当前模型不能零微调部署到 Willow。要继续这条路线，至少需要硬件域训练或校准，并重新测量端到端速度和 LER。

## 8. 合成 OOD 测试

这组测试把噪声参数系统性地推离训练分布，覆盖 `d=7`、`d=9` 和 110 个配置。每个配置、每个测量基使用 `262,144` 个 shot；每种方法合计评测 `57,671,680` 个样本。

直接答案：在这组合成分布外数据上，EWC 最好。不过它相对 SEQ 的实际优势很小，不能和 Willow 的真实硬件失败混为一谈。

| 方法 | d=7 LER | d=9 LER | 合并 LER | 合并百分比 | 合并 95% Wilson CI |
|---|---:|---:|---:|---:|---:|
| EWC | 0.226258 | 0.236210 | 0.231234 | 23.1234% | [0.231125, 0.231343] |
| SEQ | 0.226939 | 0.236821 | 0.231880 | 23.1880% | [0.231771, 0.231989] |
| Mix | 0.227405 | 0.237277 | 0.232341 | 23.2341% | [0.232232, 0.232450] |
| Replay | 0.230445 | 0.239131 | 0.234788 | 23.4788% | [0.234679, 0.234897] |
| 直接 PyMatching | 0.245546 | 0.252232 | 0.248889 | 24.8889% | [0.248777, 0.249000] |

合并后，EWC 比 SEQ 少 `0.0646` 个百分点的错误，比 Mix 少 `0.1107` 个百分点，比 Replay 少 `0.3554` 个百分点，比直接 PyMatching 少 `1.7655` 个百分点。配对 95% 区间都不跨 0。由于样本超过五千万，即使很小的差别也能被测得很精确；“差别明确”不等于“差别很大”。

输入 syndrome density 合并为 `15.617%`。EWC、Mix、SEQ、Replay 的残差 density 分别是 `2.323%`、`2.391%`、`2.408%`、`2.637%`，即减少约 `85.1%`、`84.7%`、`84.6%`、`83.1%`。这一次 density 降低同时伴随 LER 改善，与 Willow 的情况不同。

后端延迟使用独立的受控复测：仍是 110 个配置，但每个配置、每个测量基用 `10,000` 个 shot，并严格限制每张 GPU 只有一个工作进程。

| 后端输入 | d=7 μs/round | d=9 μs/round | 合并均值 μs/round | 相对直接 PyMatching |
|---|---:|---:|---:|---:|
| 原始 syndrome | 5.290 | 10.114 | 7.702 | 1.000× |
| EWC 残差 | 2.233 | 4.678 | 3.456 | 2.270× |
| Mix 残差 | 2.263 | 4.714 | 3.488 | 2.250× |
| SEQ 残差 | 2.259 | 4.718 | 3.489 | 2.250× |
| Replay 残差 | 2.363 | 4.820 | 3.592 | 2.186× |

`2.270×` 只表示 PyMatching 处理 EWC 残差时更快，不包含神经网络前向和数据搬运。合成 OOD 没有对应的完整端到端计时，因此不能说整个 EWC 解码系统提速 `2.270×`。大样本 LER 运行还采用了每卡五个并发进程，那组拥塞计时没有用于本表。

结论：最终 EWC checkpoint 在合成 OOD 上的 LER 最低，后端工作量也更小。这说明该 checkpoint 在合成噪声变化上泛化较好，但不能反过来证明“正是 EWC 训练机制导致了改善”；后一个问题主要由第 4 节的持续学习对照回答。

## 9. 结果可信度和限制

- 20 个正式及补充训练 run 都通过了配置、checkpoint 和产物审计。
- QEWC-v3 专项测试 `66/66` 通过，公共配置测试 `42/42` 通过。
- 全仓共运行 `654` 项测试，其中 `650` 项没有失败，这里面包含 `11` 项主动跳过；剩余 `1 failure + 3 errors` 都因为仓库缺少两个受访问控制的公开模型 checkpoint，与本实验代码无关。
- 配置文件可以正常读取，结果 JSON 的字段和数量正确，固定测试数据的数字指纹没有变化，代码补丁也没有格式错误。
- 最大限制是只有一个训练 seed。大量 shot 只能让“这一个模型的测试错误率”测得更准，不能证明换一个训练随机性后仍会得到相同结论。
- Stress 是人为挑选的高冲突轨道，适合检验遗忘机制，不代表实际噪声一定这么极端。
- Willow 是最接近部署问题的测试，而它给出了负结果。因此不能用合成 OOD 的正结果声称真实硬件泛化已经解决。
